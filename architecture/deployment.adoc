== Deployment Environments

=== Production Environment

Bandcheck is deployed to the Hetzner k3s cluster in the `bandcheck`
namespace. Flux reconciles the Kubernetes manifests from Git. GitHub Actions
builds versioned images. Dependabot opens PRs to update the semver image tags
in the Kubernetes manifests; Flux reconciles merged changes.

== Container Strategy

=== Backend Container

**Base Image:** `oven/bun:1` +
**Platforms:** linux/amd64, linux/arm64 +
**Size:** ~150MB (compressed) +
**Registry:** GitHub Container Registry (ghcr.io)

**Image Tags:**

* `latest` - Latest release build
* `1.0.0` - Semver tags generated from release tags

**Build Process:**

1. Checkout code from repository
2. Setup Docker Buildx for multi-platform builds
3. Authenticate with GitHub Container Registry
4. Extract metadata for tags and labels
5. Build for amd64 and arm64 architectures
6. Push to registry

**Pulling Images:**

[source,bash]
----
# Pull latest
docker pull ghcr.io/marcodoes/bandcheck/backend:latest

# Pull specific version
docker pull ghcr.io/marcodoes/bandcheck/backend:v1.0.0

# Pull from dev branch
docker pull ghcr.io/marcodoes/bandcheck/backend:dev
----

=== Frontend Container

**Base Image:** nginx +
**Purpose:** Serve static assets +
**Configuration:** Custom nginx.conf for SPA routing

== Kubernetes Deployment

=== Prerequisites

* Hetzner k3s cluster with Flux CD already bootstrapped
* Traefik Gateway API with the existing `cluster` Gateway
* cert-manager and external-dns
* Existing PostgreSQL 16 service in the `postgres` namespace

=== Kubernetes Resources

**Namespace:**

* `bandcheck` - Main application namespace

**Backend Deployment:**

* Replicas: 1
* Resource limits: CPU and memory constraints
* Health checks: Liveness and readiness probes
* PostgreSQL connection from a SOPS-encrypted Kubernetes Secret

**Frontend Deployment:**

* Replicas: 1
* nginx-based static file server
* Custom routing for SPA

**Services:**

* `bandcheck-backend` - ClusterIP service for backend pods
* `bandcheck-frontend` - ClusterIP service for frontend pods

**HTTPRoutes:**

* HTTPS on the Gateway's `websecure` listener; TLS terminates at the Gateway
* `bandcheck.cloud.marcodoes.tech` routes to the frontend
* `bandcheck-api.cloud.marcodoes.tech` routes to the backend
* API prefix supplied by the Traefik middleware

=== Setup Commands

Flux applies the application manifests from `k8s/`. The Flux bootstrap and
root reconciliation are managed separately in the `cluster-config` repository.
See `k8s/README.md` for the SOPS secret and Flux source requirements.

=== Database Management

Bandcheck connects to the existing PostgreSQL service at
`postgres-rw.postgres.svc.cluster.local:5432`. It uses a dedicated database and
role; there is no application database PVC. The PostgreSQL service's persistent
volume is not a substitute for verified backups, so confirm its backup and
restore procedure separately. Drizzle migrations are applied at backend startup.

== CI/CD Pipeline

=== Overview

The deployment pipeline uses **GitHub Actions** for continuous integration and
**Flux CD** for continuous deployment.

**GitHub Actions:**

* Builds and tests code
* Creates Docker images for frontend and backend
* Pushes images to GitHub Container Registry (GHCR)
* Tags images based on branch/version

**Flux CD:**

* Monitors Git repository for Kubernetes manifest changes
* Reconciles changes to the cluster
* Reports reconciliation status through Kubernetes resources
* Uses Git reverts for rollbacks

=== GitHub Actions Workflows

**CI Workflow (`ci.yml`):**

* **Triggers:** Push to `main` and pull requests targeting `main`
* **Purpose:** Linting, type checking, building, testing
* **Runs:** On every push and PR

**Backend Build (`backend-build.yml`):**

* **Triggers:** Backend release tags and manual dispatch
* **Actions:**
** Build multi-platform Docker images (amd64, arm64)
** Run tests
** Push to GitHub Container Registry
** Tag images with semver and `latest`

**Frontend Build (`frontend-build.yml`):**

* **Triggers:** Frontend release tags and manual dispatch
* **Actions:**
** Build React application
** Create nginx-based Docker image
** Push to GitHub Container Registry
** Tag appropriately based on branch/version

=== Flux Configuration

Flux is bootstrapped from the separate `m-gora/cluster-config` repository.
That repository defines a `GitRepository` and a Flux `Kustomization` for
Bandcheck's `./k8s` path, with SOPS decryption enabled. Dependabot monitors the
Kubernetes manifests for image tag updates.

**Deployment Process:**

1. Developer pushes code to Git repository
2. GitHub Actions builds Docker images
3. Images pushed to GHCR with appropriate tags
4. Dependabot opens a PR when a newer semver image tag is available
5. A reviewed PR is merged
6. Flux detects the Git revision and reconciles the cluster
7. New pods deploy with the updated images
8. Health checks verify deployment success

=== GitHub Secrets Configuration

**Required for All Environments:**

* `GITHUB_TOKEN` - Automatically provided by GitHub (for GHCR)
* `DOCKER_USERNAME` - GitHub username
* `DOCKER_PASSWORD` - GitHub Personal Access Token with packages:write scope

**Build-time Secrets:**

* `VITE_API_BASE_URL` - Backend API URL
* `VITE_AUTH0_DOMAIN` - Auth0 domain
* `VITE_AUTH0_CLIENT_ID` - Auth0 client ID
* `VITE_TURNSTILE_SITE_KEY` - Cloudflare Turnstile site key

**Runtime Secrets (Kubernetes):**

Stored in a SOPS-encrypted Kubernetes Secret and reconciled by Flux:

* `DATABASE_URL` - Bandcheck PostgreSQL connection URL
* `TURNSTILE_KEY` - Cloudflare Turnstile secret

== Environment Configuration

=== Frontend Configuration

**Development:**

Uses `.env` file with `VITE_` prefixed variables during local development.

**Production:**

Environment variables baked into the Docker image at build time via GitHub Actions.

**Required Build-time Variables:**

[source,bash]
----
VITE_AUTH0_DOMAIN=your-domain.auth0.com
VITE_AUTH0_CLIENT_ID=your-auth0-client-id
VITE_AUTH0_REDIRECT_URI=https://bandcheck.example.com
VITE_API_BASE_URL=https://bandcheck-api.cloud.marcodoes.tech
VITE_TURNSTILE_SITE_KEY=your-cloudflare-site-key
----

**Deployment:**

Frontend is built into a static bundle and served via nginx in a Docker container.

=== Backend Configuration

**Environment Variables:**

* `AUTH0_DOMAIN` - Auth0 tenant domain
* `AUTH0_AUDIENCE` - Auth0 API audience/identifier
* `PORT` - Server port (default: 3000)
* `DATABASE_URL` - PostgreSQL connection URL
* `ALLOWED_ORIGINS` - Comma-separated CORS origins
* `TURNSTILE_KEY` - Cloudflare Turnstile secret key
* `NODE_ENV` - Environment (production/development)

**Kubernetes Configuration:**

Configured via ConfigMap and a SOPS-encrypted Secret in the `bandcheck`
namespace, managed by Flux.

[source,yaml]
----
apiVersion: v1
kind: ConfigMap
metadata:
  name: bandcheck-backend-config
  namespace: bandcheck
data:
  PORT: "3000"
  ALLOWED_ORIGINS: "https://bandcheck.example.com"
  NODE_ENV: "production"
----

=== Cloudflare Configuration

**DNS:**

* A/AAAA records point to Kubernetes ingress IP
* Cloudflare proxy enabled for CDN and DDoS protection
* SSL/TLS mode: Full (strict) or Flexible

**Turnstile:**

* Site key configured in frontend environment variables
* Secret key stored in Kubernetes secrets
* Widget configured in submission forms

== Scaling and Monitoring

=== Manual Scaling

[source,bash]
----
# Scale backend to 3 replicas
kubectl scale deployment/bandcheck-backend --replicas=3 -n bandcheck

# Scale frontend
kubectl scale deployment/bandcheck-frontend --replicas=3 -n bandcheck
----

=== Auto-Scaling (Optional)

[source,bash]
----
# Configure horizontal pod autoscaler
kubectl autoscale deployment bandcheck-backend \
  --min=2 --max=5 --cpu-percent=80 -n bandcheck
----

=== Monitoring

**Kubernetes:**

* Pod status: `kubectl get pods -n bandcheck`
* Logs: `kubectl logs -f deployment/bandcheck-backend -n bandcheck`
* Resource usage: `kubectl top pods -n bandcheck`

**Flux CD:**

* Reconciliation status: `flux get kustomizations -A`
* Source status: `flux get sources git -A`
* Pod health and events: Kubernetes commands below

**Cloudflare:**

* Analytics dashboard for traffic patterns
* Security events and threats blocked
* Turnstile verification statistics

== Troubleshooting

=== Common Issues

**Image Pull Errors:**

Ensure GitHub Container Registry authentication is configured:

[source,bash]
----
echo $GITHUB_TOKEN | docker login ghcr.io -u USERNAME --password-stdin
----

**Database Connectivity:**

Verify the PostgreSQL service and Bandcheck database Secret:

[source,bash]
----
kubectl -n postgres get svc postgres-rw
kubectl -n bandcheck describe pod -l app=bandcheck-backend
----

**Service Not Accessible:**

Check ingress and service configuration:

[source,bash]
----
kubectl get ingress -n bandcheck
kubectl get svc -n bandcheck
kubectl get endpoints -n bandcheck
----

**Backend Startup Issues:**

View detailed logs:

[source,bash]
----
kubectl logs --tail=100 deployment/bandcheck-backend -n bandcheck
kubectl describe pod -l app=bandcheck-backend -n bandcheck
----

=== Rollback Strategy

**Flux CD:**

* Revert the Git commit that changed the manifests or image tags
* Flux reconciles the reverted Git revision
* Suspend the Flux Kustomization before any temporary manual rollback

**Kubernetes:**

[source,bash]
----
# Rollback to previous deployment
kubectl rollout undo deployment/bandcheck-backend -n bandcheck

# Rollback to specific revision
kubectl rollout undo deployment/bandcheck-backend --to-revision=2 -n bandcheck

# Check rollout history
kubectl rollout history deployment/bandcheck-backend -n bandcheck
----

**Git-based Rollback:**

* Revert Git commits containing Kubernetes manifest changes
* Flux automatically reconciles the reverted state
* Most reliable approach as it maintains Git as source of truth

== Security Considerations

* All traffic uses HTTPS/TLS via Cloudflare
* Secrets managed via Kubernetes Secrets
* RBAC configured for Flux and Kubernetes access
* Service accounts follow principle of least privilege
* CORS configured to allow only trusted origins
* Auth0 JWT validation on all protected endpoints
* Regular security updates via automated container builds
* Cloudflare provides DDoS protection and WAF
